# 服务数据

服务数据上下文保存消费者与客服发生服务关系时产生的来源事实。它回答“发生了什么”，不保存模型判断、回复建议或风险处置结论。

## 身份与轨迹

**消费者（Consumer）**：
接受咨询、购买商品或发起售后服务的自然人。消费者身份独立于登录用户、客服人员和某个平台展示昵称。
_避免使用_：用户、账号、客户、买家

**消费者别名（Consumer Alias）**：
来源系统中用于指向消费者的受限标识，例如脱敏买家昵称。别名只能在明确的来源范围内辅助归并，不能被视为天然全局唯一身份。
_避免使用_：消费者 ID、用户名

**服务会话（Service Conversation）**：
消费者与客服在一个连续接待窗口中的消息集合。一次消费者服务历程可以包含多个服务会话。
_避免使用_：聊天、Session、工单

**服务消息（Service Message）**：
服务会话中由消费者、客服或系统产生的一条有序内容记录。消息的来源标识用于幂等导入和证据引用。
_避免使用_：Prompt、回复建议

**服务轨迹（Service Journey）**：
围绕一个消费者按时间组织的会话、订单快照、服务工单和风险状态投影。它是查询视图，不是新的业务事实来源。
_避免使用_：用户画像、模型记忆

## 交易与售后事实

**订单快照（Order Snapshot）**：
从交易来源导入的订单事实副本。客服系统可以读取它，但不负责改变订单、支付、发货或退款状态。
_避免使用_：订单、交易指令

**服务工单（Service Case）**：
为处理补发换货、打款、物流、不良反应或退货问题而建立的来源记录。服务工单拥有自己的处理状态，不等同于风险预警。
_避免使用_：风险工单、任务、Ticket

**来源引用（Source Reference）**：
指向来源消息、订单快照或服务工单的稳定标识。任何面向客服展示的业务事实都应能够回到至少一个来源引用。
_避免使用_：引用文本、向量片段
