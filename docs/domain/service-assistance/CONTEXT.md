# 接待辅助

接待辅助上下文帮助客服理解当前问题并形成可编辑建议。它产生的是辅助决策，不代表消费者陈述的事实，也不直接执行售后动作。

## 分析输入

**辅助请求（Assistance Request）**：
客服或系统针对当前服务会话发起的一次辅助分析请求。每个请求绑定一个确定的上下文快照。
_避免使用_：聊天请求、模型调用

**上下文快照（Context Snapshot）**：
一次辅助分析实际使用的消息、订单快照、服务工单、有效预警和政策版本集合。快照创建后不可变，用于判断建议是否过期和复现结果。
_避免使用_：Prompt、全部用户数据

**意图判断（Intent Assessment）**：
对消费者当前主要服务诉求及细分场景的结构化判断。它是可评测结论，不是来源事实。
_避免使用_：问题类型、真实标签

**情绪判断（Emotion Assessment）**：
对当前情绪、变化趋势和置信度的结构化判断。它不能被表述为医学或心理诊断。
_避免使用_：情绪事实、用户性格

## 辅助输出

**共情建议（Empathetic Suggestion）**：
供客服审阅、编辑和选择的回复草稿及简短依据。未被客服确认前，它不是已发送消息或服务承诺。
_避免使用_：自动回复、客服回复

**处置建议（Suggested Action）**：
建议客服下一步采取的受限动作及其所需参数。建议本身不意味着动作已经执行。
_避免使用_：Tool Call、已处理动作

**证据（Evidence）**：
支撑分析事实或建议的来源引用集合。证据必须来自当前上下文快照，不能由模型创造。
_避免使用_：模型理由、思维链

**采纳决定（Adoption Decision）**：
客服对一条共情建议或处置建议作出的接受、编辑后接受、拒绝或过期决定。一个建议最多产生一个最终采纳决定。
_避免使用_：模型反馈、点赞
