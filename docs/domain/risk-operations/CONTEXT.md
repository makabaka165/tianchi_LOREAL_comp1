# 风险运营

风险运营上下文负责把服务过程中观察到的风险转化为可操作、可追踪的闭环对象。它不负责生成客服回复，也不改变订单和服务工单的来源状态。

## 识别与归并

**风险信号（Risk Signal）**：
从规则、模型或人工判断中得到的一条带证据的风险观察。风险信号可以被拒绝或合并，本身没有处置生命周期。
_避免使用_：风险预警、异常工单

**风险策略（Risk Policy）**：
规定哪些风险信号需要建立预警、最低等级、归并方式和升级条件的业务准则。模型不能降低策略确定的最低风险等级。
_避免使用_：Prompt 规则、模型评分

**风险预警（Risk Alert）**：
由一个或多个有效风险信号归并形成的可处置对象。风险预警拥有等级、负责人、状态和完整处置记录。
_避免使用_：风险信号、服务工单、通知

**归并键（Deduplication Key）**：
用于判断多个风险信号是否描述同一风险事件的稳定业务标识。它通常由消费者、风险类型和订单或工单主题共同确定。
_避免使用_：数据库唯一键、会话 ID

## 闭环

**风险等级（Risk Severity）**：
风险预警对响应速度和处置强度的要求，分为低、中、高和紧急。等级表达服务风险，不是消费者价值或责任判断。
_避免使用_：情绪分数、优先级分数

**预警状态（Alert Status）**：
风险预警在待确认、已确认、处理中、已解决或已驳回之间的业务阶段。已解决预警遇到新的独立风险时创建关联预警，而不是改写历史结论。
_避免使用_：工单状态、Agent Run 状态

**处置记录（Disposition Record）**：
负责人对风险预警执行确认、分派、备注、升级、解决或驳回时留下的不可覆盖记录。
_避免使用_：日志、聊天消息

**误报（False Positive）**：
经人工确认不构成目标风险的预警结论。误报必须保留原始信号和驳回依据，以支持后续评测。
_避免使用_：删除、模型失败
